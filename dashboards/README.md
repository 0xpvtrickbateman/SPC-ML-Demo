# AttainX Databricks dashboard

Start with **setup.html**. Open it in a browser, enter the catalog name and demo schema, and click **Download configured dashboard**. The page also provides the exact notebook setting and click-by-click import steps. It runs locally; it does not connect to the workspace.

- `AttainX_SPC_Demo.lvdash.json`: native AI/BI dashboard template. Its `demo_catalog.demo_schema` names are placeholders; use the setup helper or builder before import.
- `preview.html`: interactive companion preview generated by executing notebook Cells 1–22. The same view appears in Cell 22 via `displayHTML`. This is not a screenshot or a native Databricks rendering.
- `reviewed-data.json`: precise fictional replay and exercise rows backing the preview.
- `setup-template.html`: editable source of the setup helper. The build embeds the native dashboard definition into `setup.html`.

## Click-by-click setup

1. In Databricks, click **Catalog** in the sidebar. Click an existing writable catalog. Click **Create schema**, enter `spc_demo`, and click **Create**. If an approved dedicated demo schema exists, use that instead. Keep the catalog name; it is not the workspace name.
2. Open `setup.html` locally and type that catalog name and schema. Copy the displayed `OUTPUT_SCHEMA` setting.
3. In Databricks, click **Workspace**, open your demo folder, and use its **⋮ → Import → File** flow to import `notebooks/SPC_ML_Demo.py`. Preserve the old notebook under another name if needed.
4. Open the imported notebook. In Cell 1, set `OUTPUT_SCHEMA` to the value from the helper. Leave `UC_MODEL_NAME` empty. Attach your working Python notebook compute and **Run all**. The notebook has 22 code cells. A SQL warehouse alone cannot run its Python cells.
5. Confirm Cell 20 writes 19 tables and Cell 22 writes three more. In **Catalog → your catalog → spc_demo**, refresh and look for `demo_drift_inputs` (54 rows), `demo_drift_performance` (18), `demo_drift_daily` (450), and `review_queue` (15), filtered to `attainx_demo_v2_seed42`. Rerunning the same seed must not duplicate their keys.
6. In the setup helper click **Download configured dashboard**. In Databricks, click **Dashboards**, open the menu beside **Create dashboard**, then **Import dashboard from file**. Select the downloaded `AttainX_SPC_Demo.lvdash.json` and click **Import**.
7. Use the dashboard editor's warehouse selector to choose an existing SQL warehouse you can use. Find its name under **SQL Warehouses** in the sidebar if needed. No new warehouse is required.
8. Open the dashboard **Data** tab, run each of its ten datasets, and check for errors. Return to **Canvas** and refresh. Keep the queue filter at **Intake A** for the rehearsal. A draft dashboard is enough; publishing is a separate sharing choice.

If a query reports `TABLE_OR_VIEW_NOT_FOUND`, compare its catalog/schema with Cell 1 and confirm Cells 20 and 22 succeeded. If access is denied, the notebook identity needs table-creation/write permissions and the warehouse user needs read permissions on the selected catalog/schema/tables. Do not solve this by broadening workspace-wide privileges.

If the sidebar or button differs, use the current [schema guide](https://docs.databricks.com/aws/en/schemas/create-schema), [warehouse guide](https://docs.databricks.com/aws/en/compute/sql-warehouse), and [dashboard import guide](https://docs.databricks.com/aws/en/dashboards/automate/import-export).

## What to show

| View | Question | Evidence |
| --- | --- | --- |
| Overview | Are forecasts useful? | Saved one-day predictions, actual counts, simple baseline, latest per-queue MAE and matched actuals |
| Detect drift | What changed? | Three input distributions vs training; error across three nonoverlapping 25-day windows; missingness and sample sizes |
| Drift exercise | Can the warning fire? | Separate +35-outcome scenario; frozen predictions; one-window watch followed by two-window review |
| Review and retrain | What happens next? | Data and process investigation, candidate training, later-date validation, human approval, versioning and rollback; separate SPC queue |

The native dashboard has four pages plus a global queue filter. The notebook/local companion uses three tabs and an evidence dropdown. They use the same calculations and scenario labels. Clearing the native queue filter shows all series; daily count lines sum across queues, while error curves and tables retain each queue's identity. The SPC review queue always describes the recorded replay, never exercise outcomes.

## Drift definitions and limits

Input change uses Wasserstein distribution distance divided by training standard deviation, separately for `last_value`, `window_std`, and `trend`. A score above 0.5 prompts investigation in this demo. A constant reference with a changed value or fewer than 20 finite samples yields an unavailable diagnostic. This is not a significance test; serial dependence, seasonality and real operational context require calibration. Other numeric and categorical inputs are not monitored here.

Performance monitoring freezes the model trained in Cell 6. It divides its 75 held-out dates into three 25-day windows. Window 0 sets each queue's reference MAE; windows 1 and 2 are monitoring windows. Two successive windows above `1.25 × max(reference MAE, 1 count)` with at least 20 matched actuals each trigger **Review for retraining**. Positive bias means underprediction. Missing actuals cannot be interpreted as correct predictions.

The exercise adds 35 only to evaluation outcomes after the reference window. It leaves inputs, predictions, original counts, original metrics and the SPC queue untouched. This deliberately constructed failure tests the detector, not model accuracy or a causal hypothesis. The simple baseline is also frozen. No retraining or promotion happens automatically.

This is a fixed historical replay ending September 8, 2026. Refreshing a dashboard rereads saved tables. Running all notebook cells retrains the demonstration models. Live monitoring would need an independent scoring job using a registered model version, durable prediction/actual joins, calibrated thresholds and ongoing data-quality checks.

## Rebuild and verify locally

From the repository root:

```bash
MPLBACKEND=Agg .venv/bin/python scripts/build_dashboard.py --schema YOUR_CATALOG.spc_demo --preview
```

`--preview` executes the notebook and regenerates the preview/data files. Omit it to bind a new schema without rerunning models. The setup helper always starts with an unbound template and uses the catalog entered in its form.

The dashboard test requires `duckdb==1.4.4` in the Python test environment:

```bash
MPLBACKEND=Agg python tests/dashboard_test.py
```

The test uses a fresh unbound template, verifies drift thresholds and insufficient actuals, recomputes every MAE/bias from rows, checks scenario isolation and frozen predictions, exercises three simulated Delta MERGEs, and executes all ten unmodified dataset SQL queries in DuckDB. It also checks widget field references and nonoverlapping grid positions. Local SQL success does not prove Databricks import, Spark execution, permissions or widget rendering. Those checks are steps 5–8 above.
